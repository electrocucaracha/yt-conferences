# Summary

Here is a summary of the video transcript in 3-5 sentences: Marco Mudrin, a senior software engineer at Cubmatic and SIG K infra tech lead, discusses navigating breaking changes in Kubernetes.
He explains that breaking changes can be categorized into two types: those with mitigation (e.g., API version updates) and those without mitigation (e.g., feature removals).
To prepare for breaking changes, users should stay informed through the Kubernetes changelog, blog posts, and social media, and provide feedback on proposed alternatives to help maintainers improve the project.
The Kubernetes community also offers various resources, including mailing lists and Slack channels, for users to get involved and provide valuable feedback.
