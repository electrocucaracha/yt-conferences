# Summary

The presentation explores the interoperability challenges of Software Bill of Materials (SBOM) tools, focusing on discrepancies in package and vulnerability reporting across different solutions.
The researchers analyzed SBOMs generated by both open-source and commercial tools for popular container images, finding significant inconsistencies in the number and identification of packages, largely due to differences in how tools handle source versus binary packages and optional metadata fields.
These inconsistencies led to major variations in vulnerability detection, with some tools reporting up to ten times more vulnerabilities than others, and frequent cases where vulnerabilities were missed or incorrectly reported, especially for complex package versions or irrelevant environments.
The team demonstrated that simple mapping scripts can improve compatibility, but emphasized that true interoperability requires adherence to existing standards.
They concluded by recommending that vendors and tool developers collaborate to define common interfaces and practices, and by providing open-source tools and a UI to help visualize and address these SBOM differences.
