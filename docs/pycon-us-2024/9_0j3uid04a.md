# Summary

Liz, a developer content manager for Streamlit, presents a talk at PyCon titled "Mock it till you make it," focusing on the effective use of mocking in Python unit testing.
She explains that while mocking is essential for isolating code and avoiding external dependencies, its flexibility can lead to tests that fail silently or become irrelevant if not managed correctly.
The speaker introduces key tools from the `unittest` library, specifically `Mock`, `MagicMock`, and the `patch` decorator, emphasizing the importance of using `autospec` to ensure mocks accurately reflect the methods and attributes of the real objects they simulate.
Through a live demo of a "Build a Pug" application, she illustrates how `autospec` helps catch errors like calling non-existent methods, and demonstrates using `skip` decorators to manage test execution across different environments.
The session concludes with best practices for avoiding over-mocking, such as keeping mocks simple and refactoring code when tests become too complex, followed by a Q&A addressing common challenges in industry testing strategies.
