# Summary

Jimmy Lee, a senior engineer at ZIP, presented a framework for tackling large-scale technical debt in Python monoliths, addressing challenges such as productivity drag, unclear accountability, and the difficulty of adopting type checking in codebases with millions of lines of code.
He proposed a three-part strategy: measuring debt using custom analyzers to track specific issues like `pyright ignore` comments and `async` usage; recognizing contributions through incremental analysis of pull requests, weighted leaderboards, and real-time Slack shout-outs to foster a positive culture; and automating fixes using LSP-based commands and AI-assisted refactoring with comprehensive prompt guides.
Lee demonstrated how this approach helped ZIP boost type checking coverage from 60% to 99.6% and provided actionable insights on setting quarterly goals, generating team reports, and leveraging open-source tools to sustain momentum.
The session concluded with a Q&A discussing the balance between infrastructure setup time and execution, the importance of aligning quality metrics with business value, and the potential for using runtime data to identify deeper application logic debt.
